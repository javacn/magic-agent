## magic-agent：npm 方式打包 + 本地安装

给 Go CLI 项目 magic-agent 添加 npm 分发能力（用户要求"用 npm 方式打包安装到本地"）。

**新增文件**
- `package.json`（根）：bin 指向 `npm/bin/magic-agent.js`，`prepack` 编译、`postinstall` 兜底，`files` 白名单含源码以便现场编译
- `npm/lib/platform.js`：node 平台名 → Go 目标 / 产物路径映射，`findGo()` 多路探测
- `npm/bin/magic-agent.js`：bin 转发层，`spawnSync + stdio:inherit`（关键：保 TTY，stdin 管道读 prompt 依赖 `process.stdin.isTTY`）
- `npm/build.js`：交叉编译 5 平台 + ldflags 注入版本号
- `npm/install.js`：postinstall 兜底（永不阻断安装）

**平台拆分（修 Windows 交叉编译失败）**
`syscall.SysProcAttr{Setpgid}` / `syscall.Kill(-pid)` 是 unix-only，`GOOS=windows` 编译报错。拆成：
- `runcmd.go` 平台无关调度（`configureProcAttr` / `killProcessGroup`）
- `runcmd_unix.go`（`//go:build !windows`）Setpgid + kill 负 pid
- `runcmd_windows.go`（`//go:build windows`）`CREATE_NEW_PROCESS_GROUP`(0x200) + `taskkill /T /F /PID`
- `runcmd_test.go` 加 `//go:build !windows`（依赖 sh 脚本）
- 删 `env_unix.go`，统一为 `env.go`（`os.Environ()` 本就跨平台）

**产物**：`magic-agent-0.1.0.tgz`（6.6MB / 解开 16MB，含 darwin-arm64/x64、linux-x64/arm64、win32-x64）

**验证结果**（全部真跑通过）
- `go test ./...` 全绿；`GOOS=windows go vet ./...` 无告警
- 全局装：`magic-agent` 落在 `/Users/m10003000247/.workbuddy/binaries/node/versions/22.22.2-3/bin/`（该目录已在 PATH，装完即可用）

## 追加：装错 npm 前缀 + `--version` 缺失（16:30）

超哥反馈 `magic-agent --version` → `zsh: command not found: magic-agent`。两个独立原因：

**1. 上一轮装错位置（我的疏忽）**
装到了 WorkBuddy 沙箱注入 PATH 的 node（`~/.workbuddy/binaries/node/versions/22.22.2-3/`），
**该目录不在超哥 zsh 登录 shell 的 PATH 里**。超哥真实环境是 Homebrew node v25.6.1 / npm 11.9.0，
prefix `/opt/homebrew`。
→ 正确做法：用 `which -a npm` / `npm config get prefix` **先确认用户真实 npm**，再用绝对路径 `/opt/homebrew/bin/npm install -g`。
教训：**在 WorkBuddy 沙箱里验证通过 ≠ 在用户 shell 里可用**，安装类任务必须用登录 shell 复核（`zsh -lc '...'`）。

**2. `--version` 当时确实不支持**
只有 `version` 子命令，cobra 未设 `Version` 字段 → `unknown flag: --version`（exit 1）。
→ 修：root 加 `Version: Version` + `SetVersionTemplate("{{.Name}} {{.Version}}\n")`，
   使 `--version` 与 `version` 输出一致（`magic-agent 0.1.0`）。

**顺带修的真实缺陷（并发写入者引入）**
`internal/cli/ask_test.go` 的 `toolsModeChecker` 接口用**非导出方法**（`isOff`/`isOn`/`allowlistOf`），
但实现方 `toolsModeImpl` 在 `agent` 包 —— Go 中跨包非导出方法名带包路径，**永远无法满足接口**，测试稳定失败。
→ 修：`ToolsMode` 接口方法改为导出（`IsOff`/`IsOn`/`Allowlist`），三个引擎调用点与测试断言同步更新；
   `toolsOrDefault` 改为返回接口；保留并发写入者加的 `ToolsIsOff`/`ToolsIsOn`/`ToolsAllowlistOf` 包装。

**新增测试**：`TestAskDefaultOutputJSON`、`TestVersionFlagAndSubcommand`、`TestAskSubcommandInheritsFlags`。
同步修正 2 个旧测试（默认输出已由 text 改 json，需显式 `-o text`）。
另修 `bindAskFlags` 用 `cmd.Flags()` → `cmd.PersistentFlags()`，否则 `ask` 子命令无法继承 flags（`pflag.NotExistError`）。

**⚠️ 重要环境观察**：本轮期间**有另一个写入者在同时修改该仓库**——
`claude.go`/`codebuddy.go`/`engine.go`/`trae.go`/`ask_test.go` 在 16:24–16:27 陆续被改，
还出现过 `tm_check_test.go`（`TestTMDebug` 探针，后被其自行删除）。这些**不是我写的**。
在此仓库做改动前应先确认无并发写入，否则改动可能被覆盖。
